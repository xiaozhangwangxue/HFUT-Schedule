# 聚在工大 iOS 1.2.1

日期：2026-11-14。修复用户在重签名安装 1.2.0 后，App 已有课程而桌面小组件仍显示「还没有课表数据」的问题。上游同步基线继续使用 `b3cb252e`，原有功能和验证历史保留在 [1.2.0 更新说明](1.2.0.md)。

## 问题与修复

1.2.0 从文件加载已有课表后，没有像保存课程时一样立即重新发布小组件快照；共享钥匙串还固定使用维护者的团队前缀。升级后只有旧数据、或用其他团队重签名时，App 中的课程可能没有进入 Widget 实际可读的通道。 另外，旧的纯 unsigned 包没有 Mach-O 签名 entitlement；侧载工具无法从中保留所需共组声明，可能为两个目标生成独立私有组。

- **启动与前台同步**：成功加载已有本地课表后重新发布，回到前台也可重发，不要求用户先修改课程。
- **签名前缀可移植**：App 与 Widget 的共组 entitlement 使用动态 `AppIdentifierPrefix`。运行时不写死访问组，遵循当前签名授予的组。
- **有效空快照**：用户清空课表后，新空快照压过旧共享或包内数据；缺失 / 损坏的本地文件不会被当成主动清空。
- **明确学期基准**：v2 快照携带 `termStart`，小组件优先使用 App 计算的学期开始日期；仍兼容旧版数组快照。
- **读取回执**：扩展实际读取后写回对应快照的 ACK。写入成功、App 回读成功或请求刷新，都不能单独表示扩展已读到。

## 查看状态和手动发送

打开「**选项 → 偏好与配置 → 桌面小组件**」，可查看本地课表发送状态、共享写入结果和扩展读取确认，并手动发送当前课表。

若已经写入但还没有当前快照的扩展回执，状态会保留为等待确认，而不声称同步完成。WidgetKit 的刷新由系统调度，手动发送请求刷新后不保证立刻显示。

公共源码与公共 IPA 继续使用空快照，不包含任何个人课程、教师、地点或认证数据。修复依靠共享通道与回执，不能用打包私人课表替代。

## 重新签名要求

- 必须保留包内 Widget 扩展，并一起签名。
- App 和 Widget 必须使用同一团队授权的同一个 Keychain 共享组；由于运行时使用默认组，该组应当是两个目标的首组。
- `AppIdentifierPrefix` 以实际描述文件为准，不应直接当作团队标识，也不能保留维护者前缀。
- 临时签名脚本从两个描述文件验证共组；其他侧载工具也必须保留这些设置。不能保证每个工具或每种签名方式都能满足条件。

对已经签名的包，可执行：

```sh
./ios/HFUTSchedule/scripts/verify_widget_signing.sh /absolute/path/to/signed.ipa
```

脚本只读检查 App、Widget、实际签名 entitlement、描述文件授权和签名完整性，输出状态而不输出个人设备标识或证书内容。它只适用于**签后的包**；未签名 IPA 不能通过它证明共享能力，签名结构通过后仍需在真机查看扩展 ACK。

当前 Apple 能力表对免费 Apple Developer 列列出了 App Groups 与 Keychain Sharing。因此不再笼统断言免费团队一律不支持 App Groups；实际可用性仍取决于 Xcode、描述文件、签名与容器权限。共享钥匙串和 App Group 是不同通道，创建一个同名偏好对象不代表获得了共享容器。

## SDK 与 Duo 动态窗口

发布构建使用 **iOS 27.2 SDK**，最低运行版本继续为 iOS 17.0。 本机 CoreSimulator 拒绝为现有 27.2 runtime 创建 Duo 设备，因此 Duo 专用运行测试采用 27.2 SDK 编译、27.1 Duo runtime；27.2 系统测试在 iPhone 18 Pro 模拟器完成。网格按当前窗口宽度和动态字体计算列数并限制内容宽度，随窗口大小、旋转和 Duo 动态窗口变化调整，不按设备名称硬编码。

## 获取与安装

侧载安装优先下载 **`HFUTSchedule-iOS-1.2.1-resignable.ipa`**，见 [GitHub Releases](https://github.com/xiaozhangwangxue/HFUT-Schedule/releases/tag/ios-v1.2.1)。它用无证书的 ad-hoc 签名，在 App 与 Widget 的 Mach-O 中嵌入相同的唯一首组声明。`RESIGN0000` 仅为占位前缀，不是任何人的开发者身份；侧载工具必须将其改成用户获授权的前缀。包内不含描述文件，不能直接安装。

另提供 `HFUTSchedule-iOS-1.2.1-unsigned.ipa`，用于自行按本仓库脚本完整配置签名的情况。仅对纯 unsigned 包自动生成私有签名组，可能继续导致 Widget 无法共享。

构建待重签包：先运行 `build_unsigned_ipa.sh`，再运行 `build_resignable_ipa.sh`。后者拒绝个人课表、描述文件、不安全归档路径，并对两个目标的同首组、ad-hoc 签名和包体完整性进行检查。

AltStore/AltSign 与 SideStore/SideSign 的固定源码版本会从原 Mach-O 读取组名，保留首个点之后的后缀并重写前缀：[AltSign 实现](https://github.com/rileytestut/AltSign/blob/e639bdfbea185d5c229b11f62e25c5d78649d5c4/AltSign/Signing/ALTSigner.mm#L353-L392)、[SideSign 实现](https://github.com/SideStore/SideSign/blob/752d1ef602aa792a432ffa1e71646dc1ecf7363c/Sources/CodeSigning/CodeSignerAPI.swift#L98-L121)。这支持提供元数据变体，但不能代替对用户所用工具版本、最终授权组及真机 ACK 的核验。

安装时保留 Widget 扩展，更新后先打开 App；如需确认，进入「选项 → 偏好与配置 → 桌面小组件」查看读取回执。
