# 聚在工大 iOS 1.3.1

日期：2026-11-25。版本：**1.3.1 build 8**。最低 iOS 17；使用 iOS 27.2 SDK，在 iOS 27.3 真机验证本次问题。

## 登录与闪退

- 修复原生登录页随父视图重绘重新创建 CAS 客户端的问题。已取得的 execution、验证码与密钥现在保留在同一会话中，点击登录不会因客户端更换而误报“未获取到 CAS 加密密钥”。新增实际 SwiftUI 页面重建回归测试。
- 兼容多条 Set-Cookie 的合并、无空格逗号、换行以及 WebVPN 虚拟 Cookie 的引号 / JSON 字符串包装；正确保留 Expires 中的逗号。读取当前响应，不用旧 Cookie Jar 中的密钥补缺。缺失参数时最多重新准备一次，不自动重试密码提交。
- 修复全局深链 / 快捷入口打开的登录窗口没有完整继承共享数据对象的问题，避免登录回调使用这些对象时触发 SwiftUI 退出。
- WebVPN 登录后确认实际 CAS TGC，将同一凭据限定到原 CAS 域名和 `/cas/` 路径，供其他校园平台继续 SSO；HTTP 200 和匿名 SESSION 不再冒充成功。
- 信息门户按正式回调 URL 解析 OAuth code，校验来源，允许有效 code 使用不同前缀；认证链短暂失效时重新获取一次。
- 第二课堂不再在网站根路径查找限定于 `/scReports` 的 Cookie。完成重定向后按实际页面路径读取会话，再查询活动列表。

## 电费只选择一次宿舍

合肥校区把同一校区、楼栋和南 / 北 / 中区域的“照明”“空调”列表项合并为一个宿舍选项。房间只选择一次，程序按校方实际显示名称匹配两类电表各自的楼栋及房间编码，再分别请求余额；不猜测编码或将一个电表重复显示为两类余额。宣城原有一次选择、分类型查询继续保留。

旧默认配置在校方返回明确匹配项时补齐另一电表并保存。名称不匹配、对应项缺失或存在歧义时，不擅自查询其他房间，也不把失败显示为零。
