# 聚在工大 iOS 1.2.3

日期：2026-11-22。版本：**1.2.3 build 5**。为原生 CAS 登录页补齐与原项目对应的图片验证码自动填写，覆盖校园网直连和 WebVPN 两种登录方式。

## 本地识别与自动填写

- 使用 **Tesseract** 在本机识别登录页已经取得的验证码图片，先灰度处理，再按单行文字识别。识别不调用远程 OCR 服务，也不上传验证码图片。
- 验证码图片加载后尝试自动填写；点击刷新图片或重新准备登录会话后，针对新图片重新识别，旧图片的迟到结果不能回填新表单。
- 输入框保持可编辑。用户手动输入或修改验证码后，以手动内容为准，不让同一图片的识别结果覆盖人工修改。
- 关闭自动填写开关后取消当前自动填写任务，后续结果不再回填；仍可看图手动输入和刷新图片。
- 识别失败或没有可用结果时可继续手动输入。自动填写不代表验证码已被学校校验，也不会自动点击登录、提交表单或反复尝试登录。

识别只作用于 App 的原生 CAS 验证码输入框，使用当前登录会话取得的图片。它不向任意网页注入验证码识别或填写，不处理短信验证码，也不改变校方认证与 WebVPN 会话要求。获取验证码图片和提交登录仍使用原有校方请求链。

## 引擎、模型与上游差异

iOS 通过 Swift Package Manager 固定使用 [`SwiftyTesseract/libtesseract` 0.2.0](https://github.com/SwiftyTesseract/libtesseract/tree/214a36e04d740795d7ba2f07c6108944d0136f8a)，所用引擎为 Tesseract 4.1.0。工程内置仓库 [`tools/Captcha-Ocr/成品/captcha.traineddata`](../../tools/Captcha-Ocr/成品/captcha.traineddata) 的训练模型，资源位于 `HFUTSchedule/Resources/tessdata/captcha.traineddata`，以 `captcha` 语言加载，安装后无需另行下载 OCR 模型。

Android 原项目使用 Tesseract4Android，并由用户下载或导入名为 `eng.traineddata` 的模型；没有模型时不能直接启用识别。2026-11-22 核对的 [Android 下载模型](https://gitee.com/chiu-xah/HFUT-Schedule/releases/download/Android/eng.traineddata)、仓库 `tools/Captcha-Ocr/成品/captcha.traineddata` 和 iOS 内置模型均为 **11,697,722 字节**，SHA-256 均为 `c419bb2456ed54477b29dd8f2020ba6a351cd42796fbcfcf42af08655c8cafcc`，因此本版本使用同一个训练模型，文件名和加载语言按平台分别配置。

相同模型不保证不同引擎版本、设备和图片下的结果完全相同，也不代表验证码识别率已获真实校方登录验证；训练库抽样回归的结果另列于验证章节。

上游运行时没有固定四位长度或字符白名单校验。训练目录的字符集文件包含小写英文字母和数字；客户端不应仅凭常见样本长度就将其他长度的识别结果截断。是否填写成功仍以用户核对和学校登录响应为准。

## 构建、签名与安装

运行要求仍为 iOS 17.0 及以上，发布构建使用 iOS 27.2 SDK。首次构建需解析固定版本的 Swift Package 依赖，设备包中需保留 `tessdata/captcha.traineddata`。

侧载继续优先使用 **`HFUTSchedule-iOS-1.2.3-resignable.ipa`**，使用自己的侧载工具重新签名后安装；另提供 `HFUTSchedule-iOS-1.2.3-unsigned.ipa` 给自行完整配置签名的构建者。Widget 扩展与两个目标共同首个授权 Keychain 组的要求，以及 SDK、Duo 和 Widget ACK 方案，继续沿用 [1.2.1](1.2.1.md)。

公共包不包含私人课表、账号、Cookie、密码或 API Key。OCR 模型是公开训练资源，不能用模型识别测试代替真实校方登录、网络和用户重签后的真机验收。
